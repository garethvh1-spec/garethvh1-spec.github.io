Raspberry Pi 5 vs Lenovo M720q: Measured Side by Side for a Homelab

The Pi 5 is a genuine server; the M720q is a genuine step up. I run both in the same 10-inch rack, tested them with the same benchmarks, and have real numbers for where each one wins and where it doesn't matter.

What I'm actually running

My rack is a 10-inch 6U Lab Rax system holding a UniFi Cloud Gateway Fiber, a UniFi USW Flex 2.5G 8 PoE switch, a UniFi U5G for 5G backup internet, a Lenovo M720q in a 3D-printed rack mount, and Raspberry Pis in a 3D-printed three-Pi mount. A UniFi U7 Pro XG access point is powered by PoE from the same switch.

The Raspberry Pi 5 Model B Rev 1.1 (16 GB RAM) runs Raspberry Pi OS on Debian 13 (trixie), booting from a Fanxiang S501Q 512 GB NVMe via the M.2 HAT+ at PCIe Gen 2. It draws power exclusively from PoE — no wall PSU at all. It handles 13 always-on services: trading bots, a content pipeline, monitoring, and a dashboard.

The Lenovo ThinkCentre M720q Tiny (Lenovo ThinkCentre M720q Tiny, bought refurbished) runs Proxmox VE 9.2 on Debian 13, booting from a Samsung PM9A1 1 TB NVMe. It has 32 GB RAM, with one empty 2.5-inch SATA bay and an optional PCIe x8 riser slot. Right now it hosts an LXC Samba file server, an LXC Syncthing phone-photo backup (16 GB, 4,181 files), and a nightly pull-backup of the Pi that I've restore-tested.

I paid £345 for the M720q in October 2026, refurbished, including the 32 GB RAM and 1 TB NVMe. I didn't record what the Pi build cost, so I can't give you a fair cost comparison — price a Pi 5 with NVMe HAT, storage, PoE HAT, and a case on the day if that matters to you.

The benchmarks — same tests, same day

All disk tests were run with fio (1 MB sequential and 4K random at queue depth 32, direct I/O, 15 seconds each). CPU tests used the 7-Zip built-in benchmark.

Disk

Test Pi 5 (Fanxiang S501Q, Gen 2) M720q (Samsung PM9A1) Ratio
Sequential read 452 MB/s 3,424 MB/s 7.6×
Sequential write 431 MB/s 3,242 MB/s 7.5×
Random read 4K QD32 104,978 IOPS 158,595 IOPS 1.5×

The sequential gap is enormous — 7.6× — and it's mostly the PCIe link. The Pi 5's M.2 HAT+ runs at Gen 2 by default, which caps the bus around 500 MB/s. The M720q's PM9A1 is on a full Gen 3 ×4 link. On random 4K reads the gap tightens to 1.5×, because random I/O bottlenecks on the drive's controller more than the bus width.

If you're running a file server, doing VM image moves, or restoring backups, the M720q's sequential throughput makes a tangible difference. For lightweight container workloads that mostly do small random I/O, the Pi's 105K IOPS is genuinely fine.

CPU

Test Pi 5 (4× A76) M720q (i5-9400T, 6 cores) Ratio
Single-thread 7-Zip 4,463 MIPS 5,473 MIPS 1.2×
All-threads 7-Zip 16,011 MIPS 29,506 MIPS 1.8×

Single-thread, the i5-9400T leads by only about 22%. The Pi 5's Cortex-A76 cores are surprisingly competitive clock-for-clock. The real gap is multi-thread: six cores versus four gives the M720q an 84% lead. If you're running Proxmox with multiple VMs and containers doing actual work simultaneously, that headroom matters. For a single-purpose Pi running a handful of lightweight services, 16K MIPS is plenty.

Thermals

Pi 5 M720q
Idle 50.7 °C 28.0 °C
After sustained load 54.0 °C 39.0 °C

The Pi idles at 51 °C with no undervoltage or throttle flags, and only climbs to 54 °C under load — the PoE supply reads 5.16 V, solid. The M720q's fan and larger heatsink keep it at a cool 28 °C idle, 39 °C loaded. Neither machine throttles, but if you're stacking three Pis in a closed 10-inch rack, their combined idle heat is worth thinking about. The M720q runs cooler despite doing more work.

The rack and 3D printing

Both machines sit in mounts I printed in PETG on a Bambu Lab P1S. The designs are community creations downloaded from Bambu Lab MakerWorld — I didn't design or model them. Assembly uses standard nuts and bolts, no heat-set inserts. PETG is commonly recommended for rack mounts because it handles higher temperatures than PLA (glass transition typically around 80 °C vs ~60 °C for PLA) and resists creep under sustained load, though I didn't do any formal strength or heat testing on these specific prints.

The PoE lesson

With the Pi connected to both PoE and its wall PSU, a breaker trip left it powered off when mains returned — the two power sources raced on restore. Running PoE only fixed it cleanly. Now, pulling the network cable and re-inserting it boots the Pi by itself. If you're running a Pi on PoE, commit to it: remove the wall PSU entirely.

The 5G backup

The UniFi U5G sits in the rack as WAN failover for the Cloud Gateway Fiber. It uses 5G RedCap (standalone only, with LTE fallback) and connects via a single Gigabit Ethernet port powered by 802.3af PoE. Published specs list 220 Mbps down / 120 Mbps up on 5G and 195 Mbps down on LTE. It takes one nano-SIM or one eSIM — not both simultaneously.

I haven't measured my own speeds, latency, or failover time. One US reviewer on Google Fi with average indoor signal reportedly saw roughly 30–85 Mbps down and 1–3 Mbps up. The device needs a UniFi gateway running Network 10.4.57 or later; it won't work with a third-party router. If you're on a capped mobile data plan, turn off UniFi's Automatic Speed Test — it will burn through your allowance.

Who should NOT do this

Don't buy a refurbished M720q if a Pi already covers your workload. If you're running Pi-hole, Home Assistant, and a few containers, the Pi 5's 105K random IOPS and 16K MIPS are more than enough. The M720q is worth it when you need virtualisation headroom, more RAM (32 GB vs the Pi's 16 GB max), or the sequential disk speed for file serving and backups.

Don't assume 3D-printed rack mounts are plug-and-play. Tolerances vary between printers, and PETG can warp if your bed adhesion isn't dialled in. Budget an evening for test fits and reprints.
